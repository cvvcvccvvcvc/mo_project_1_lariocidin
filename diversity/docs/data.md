# Карта данных diversity

Здесь разделены **решения о выборке**, **скачанные байты**, **производные файлы** и **результаты**. Имя файла не заменяет provenance: для конкретной загрузки смотрите `inputs/provenance/`, для состава анализа — `inputs/selections/`, для порогов — `protocols/`.

| Путь от `diversity/` | Что хранится и почему |
|---|---|
| `environment/` | Рецепт окружения и lock-файлы Linux/macOS. Создаваемая `.env/` исключена из Git. |
| `protocols/` | Два зафиксированных машинных правила курации и `diversity_controls_scope.json`. Они задают критерии, не содержат скачанные данные. |
| `inputs/selections/` | Закреплённые accession и решения: `baseline/`, `species/`, `extension/`, `controls/`, `review/`; `shards/` содержит 17 частей поиска. Пилотные выборки и прежние HGT-списки удалены из текущего дерева. Новый пробный прогон пишет свои выборки и журнал в игнорируемую `.local/pilot/`. |
| `inputs/provenance/` | URL, версии, SHA-256 и журналы загрузки; `shards/` — журналы тех же 17 частей. `historical/` — неизменённые манифесты прошлого запуска с прежними путями. Генерируемые `diversity_domain_search.json` и `diversity_extension_scope.json` — свидетельства выполненной подготовки, не протоколы. |
| `inputs/archives/` | Малый `source_snapshots.zip` содержит исходные metadata литературного и Maize baseline. Два крупных ZIP для полного diversity-поиска вне Git; их размер и SHA-256 перечислены в `inputs/provenance/off_git_assets.tsv`. Старый архив копий скриптов и неиспользуемая начальная выборка удалены. |
| `data/raw/` | Неизменённые загрузки, все вне Git. `reference/` и три файла в корне нужны проверочному reference; `research_2026-09-10/`, `s3/`, `focal_context/` — литература и Maize baseline; `diversity_2026-10-12/`, `diversity_2026-10-13/` — исходные metadata и проверка носителей; `diversity_proteomes/`, `diversity_contexts/`, `diversity_extension_2026-10-13/` — основной поиск, окружения и расширение. Даты обозначают зафиксированный снимок источника. |
| `data/interim/` | Пересоздаваемые временные файлы baseline и Maize, вне Git. Старые диагностические TXT убраны из рабочего каталога. |
| `data/processed/reference/` | Небольшой контрольный набор LrcC и его производные; остаётся в Git для быстрой проверки. |
| `data/processed/literature/` | Литературный набор cyclase/precursor и разметка BGC. Калибровка профилей создаёт HMM и диагностические файлы в игнорируемом `results/profile_calibration/`; этот каталог пересоздаётся baseline-заданием. |
| `data/processed/maize/` | Производные Maize-кандидаты и контекстные окна baseline. |
| `data/processed/discovery/` | Большие производные видового, межсредового и контрольного поиска; `contexts/` разделён по shard. Вне Git, восстановим из зафиксированных входов при наличии внешних архивов. |
| `results/tables/` | Этапные таблицы создаются заново и исключены из Git; две итоговые таблицы оставлены как небольшое проверяемое свидетельство. `results/logs/`, `iqtree/`, `figures/` тоже локальные. Поэтому подкаталог `tables/` здесь оправдан даже если в clone видны только два файла. |

`inputs/` и `data/` решают разные задачи: первое фиксирует **что и откуда брать**, второе хранит полученные и переработанные байты. Папки `raw`, `interim`, `processed` описывают степень обработки, а не отдельные гипотезы. Не редактируйте скачанный `raw`; при смене источника создавайте новый снимок и манифест.

Координаты в экспортированных BGC-record заданы как zero-based half-open и не обязаны совпадать с координатами полной сборки. Неверсионированный accession нельзя молча обновлять до текущей версии.

Полный исторический запуск использовал 41,5 GiB протеомов и внешние архивы метаданных. Один clone пока не восстанавливает эти архивы; перед повтором получите их отдельно и проверьте `sha256sum -c inputs/provenance/off_git_assets.sha256`. Крупные данные и окружение держите вне Git. Старый HGT-поиск из diversity исключён: текущая [HGT-линия](../../hgt/README.md) владеет собственными входами и результатами. Новый экспорт для неё создаётся только отдельным вызовом `scripts/steps/export_diversity_handoff.py --output <новый-путь>` после проверки итоговых таблиц.
