# Поиск разнообразия лариоцидиноподобных BGC

**Состояние 13.10.2026:** окончательный пересмотр 8 540 сохранённых окружений дал 201 группу BGC-кандидатов: 89 canonical и 112 noncanonical. Ещё 8 335 номинаций остались неопределёнными. [Итог и ограничения](RESULTS.md), [полный каталог](results/tables/diversity_final_BGC_catalogue.tsv), [краткая сводка](results/tables/diversity_final_catalogue_summary.tsv). Это предсказания по зафиксированной выборке, не доказательство функции или глобальной новизны.

## Что где лежит

| Каталог | Назначение |
|---|---|
| `protocols/` | Пороги и правила отбора; менять их после просмотра результатов без новой версии нельзя. |
| `inputs/selections/` | Состав выборок и ручные решения; CSV/TSV здесь являются входами, а не параметрами программы. |
| `inputs/provenance/` | URL, версии, SHA-256, журналы загрузок и run manifests. |
| `inputs/archives/` | Крупные архивы метаданных вне Git; контрольные суммы в `inputs/provenance/off_git_assets.tsv`. |
| `data/raw/`, `data/interim/` | Скачанные и временные большие данные вне Git. |
| `data/processed/` | Воспроизводимые reference-файлы и `discovery/` с материалами поиска. |
| `results/` | В Git остаются только итоговые таблицы; промежуточные таблицы и логи восстанавливаются расчётом и остаются локально. |
| `scripts/` | Расчётный код и задания Slurm; порядок запуска ниже, остальные скрипты — внутренние этапы. |

## Быстрая проверка

Из этого каталога на машине с micromamba/conda:

```sh
micromamba create -y -p .env -f environment.yml
bash scripts/run_reference.sh
.env/bin/python -m unittest discover -s tests -v
```

`run_reference.sh` восстанавливает ограниченный опубликованный reference, сверяет его SHA-256 и строит контрольные результаты. Источники указаны в `inputs/selections/sources.tsv`, ожидаемые хеши — в `inputs/provenance/checksums.sha256`.

## Полный анализ

1. На Linux создайте `.env` из `environment.linux-64.lock`, затем поместите внешние архивы в `inputs/archives/` и проверьте `sha256sum -c inputs/provenance/off_git_assets.sha256`. До публикации архивов полный исторический повтор требует получения этих файлов у автора работы.
2. Запустите `bash scripts/submit_baseline.sh`: он проверит архивы и отправит один Slurm job для опубликованного reference, литературного и Maize baseline, затем подготовки diversity-источников и сравнительных файлов. Проверьте успешное завершение задания до следующего этапа.
3. Отправьте видовой поиск, контексты и сборку одной командой `bash scripts/submit_species.sh`; она задаёт Slurm-зависимости и не запускает анализ на login node. После видового этапа отправьте `bash scripts/submit_additional.sh extension` и `bash scripts/submit_additional.sh controls` (по отдельности либо параллельно, соблюдая общую квоту). Они используют собственные зафиксированные выборки и сами связывают Slurm-задания. Исторические run manifests фиксируют исходные входы и результаты.
4. После всех 17 context-shards выполните `bash scripts/submit_diversity_review.sh`. Скрипт проверяет входы, ставит повторную курацию и сборку с зависимостью. Сравните итог с `RESULTS.md`; для нового HGT-снимка используйте `export_diversity_handoff.py --output <новый-каталог>`, не перезаписывая снимок 13 октября.

Полный поиск загрузил 41,5 GiB протеомов. Пилот `screen_diversity_proteomes.py --limit 12` проверяет установку, но не заменяет полную выборку. Данные и неполные задания не надо интерпретировать как отрицательный результат. Для решения о новом поиске или изменении критериев см. [краткий план](../../../docs/lariocidin-plan.md).
