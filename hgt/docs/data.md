# Карта данных HGT

HGT работает с отдельным снимком, а не с текущими файлами diversity. Пути ниже считаются от `hgt/`. Небольшие протоколы, выборки и итоговые таблицы находятся в Git; тяжёлые снимки, окружения, промежуточные расчёты и Slurm-журналы живут локально вне истории Git.

| Путь | Назначение |
| --- | --- |
| `inputs/2026-10-13/` | Исходные опубликованные архивы, reference и версии внешних методов для H1; локальный снимок вне Git. |
| `inputs/H1_2026-10-13/` | Скачанные геномы, метаданные и производные H1 для связи локусов с носителями; вне Git. |
| `inputs/H2_2026-10-13/` | Зафиксированный вход H2, включая собственную копию H1, reference и версии кода; вне Git. |
| `config/sources/` | Источники литературы, загрузок и внешнего кода. |
| `config/H1/` | H1 accession, кураторские решения, манифесты и контрольные суммы. |
| `config/H2/` | Два протокола H2, состав панелей, решения по ортологии/моделям, входные и итоговые манифесты. Архивные решения о пилотах и квитанции запуска здесь **не** являются командами для повторного расчёта. |
| `results/tables/`, `results/H1_sequences/` | Таблицы H1 и локальные последовательности/BLAST. Таблицы, на которых основаны выводы, уже зафиксированы в Git; новые неотслеживаемые выходы игнорируются. |
| `results/H2/` | Деревья, карты листьев, QC, сравнения и рисунки; `actino/` — отдельная панель, `comparisons_partial/` — только готовая часть H2. `pilots/` и `run_checkpoints/` — исторические диагностики, не основные деревья. |
| `results/slurm/`, `results/cache/`, `tools/` | Журналы/ID заданий, кэш и локальные инструменты; игнорируются Git. |
| `provenance/historical/` | Неизменные манифесты старых расположений и запусков; проверяются относительно старого commit или сохранённого снимка. |
| `provenance/2026-10-14-H2-ready-tree-comparison.md` | Замороженный подробный отчёт готовой части H2, включённый в `config/H2/H2_ready_result_manifest_2026-10-14.json`; текущий краткий вывод — в [результатах](results.md). |

Для исторического полного повтора одного клона недостаточно: оператор отдельно получает три именованных снимка и сверяет URL, accession/version, размеры и SHA-256 с `config/sources/`, `config/H1/`, `config/H2/` и `provenance/historical/`. `*.sha256` запускаются из `hgt/` против **соответствующего снимка**, а не против произвольно обновлённых файлов. Повтор запускайте в отдельном checkout: часть итоговых файлов отслеживается Git и пересчитывается на месте. Не заменяйте данные из живого API внутри старой версии анализа. Создавайте новый снимок, если изменился вход.

Для Linux окружения используйте перечень Python-пакетов `config/H2/H2_python_dependencies.txt` и зафиксированный набор бинарников `config/H2/H2_tools_explicit.txt`. Они описывают использованные зависимости, но сами не поставляют геномы. Расчёты идут через Slurm; планируйте в пределах 64 CPU, 512 GiB RAM и 250 GB диска, проверяя текущую квоту на кластере. SSH alias и абсолютные пути хранятся вне репозитория; базовый вход в кластер описан в [главном README](../../README.md).
