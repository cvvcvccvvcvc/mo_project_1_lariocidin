# Правила работы над лариоцидином

Это корень Git и единственная область проекта. `README.md` — вход для человека; этот файл — короткий маршрут для агента. Читайте только код и документ, владеющие текущей задачей.

| Задача | Начать с |
| --- | --- |
| Вопрос, гипотезы, границы вывода | `docs/research.md` |
| Поиск BGC: метод, данные, выводы | `diversity/docs/method.md`, `diversity/docs/data.md`, `diversity/docs/results.md` соответственно |
| HGT: метод, входы, состояние и выводы | `hgt/docs/method.md`, `hgt/docs/data.md`, `hgt/docs/results.md` соответственно |

## Инварианты исследования

- Diversity и HGT используют разные зафиксированные снимки. Новую выборку передавайте в HGT только как новый именованный снимок с provenance и отдельным решением; старый вход не перезаписывайте.
- Сохраняйте accession/version, URL, SHA-256, версии инструментов, commit и параметры запуска. Исторические манифесты относятся к прежнему снимку; не подгоняйте их хеши под новую структуру.
- Предсказанный BGC не подтверждает продукт; конфликт деревьев сам по себе не доказывает HGT. Отделяйте завершённые результаты от пилотов и незаконченных заданий.
- Геномы, архивы, окружения, журналы, учётные данные, адреса кластера и личные пути не попадают в Git. Крупные входы сверяйте по манифестам.

## Изменения и документация

- Для кода и структуры применяйте `engineer-change`: сначала проверьте действующий маршрут, затем делайте самое простое **полное** изменение; удаляйте устаревшие ветви и файлы, не плодите адаптеры и абстракции без измеренной нужды. Проверяйте затронутую границу соразмерно риску.
- Для документации применяйте `agent-project-documentation`: у каждого факта один текущий владелец; ведите агента от задачи к нужному документу и коду, раскрывая подробности по теме. Удаляйте дубли и устаревшее вместо накопления README и отчётов. Точные команды, форматы и пороги проверяйте в коде или зафиксированном протоколе; обновляйте ссылки при перемещении.
- Коммитьте каждое законченное, проверенное изменение отдельно: одна причина и один проверяемый результат на коммит. Добавляйте в индекс только его файлы; не смешивайте уборку, научные критерии и новые результаты. Перед коммитом проверьте затронутый маршрут и `git diff --check`; после работы оставьте чистое дерево.
